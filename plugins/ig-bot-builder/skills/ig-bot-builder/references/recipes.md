# Instagram bot 案例與填寫方式

案例只示範如何做決策，不是要求 Agent 支援所有產業或照搬技術棧。

## 空白決策卡

| 欄位 | 要回答的問題 |
|---|---|
| 目標 | 誰需要這個帳號提供什麼價值？ |
| 來源 | 素材從哪來、是否有權使用、多久算過期？ |
| 圖像 | 自有圖、程式排版或其他；手機上如何驗證？ |
| 觸發 | 固定、事件、webhook 或人工？沒素材時怎麼停？ |
| 去重鍵 | SKU、slug、來源 URL、檔案 hash 或其他業務鍵？ |
| 人工 gate | 使用者批准時要看到哪些完整資訊？ |
| 紅線 | 商業揭露、人物、價格、YMYL 或其他風險？ |

## 原作者實跑案例：AI／股市新聞圖卡

作者曾實際運作約三個月。這個案例的價值是故障證據，不代表新聞或股市是
推薦用途。

| 欄位 | 決策 |
|---|---|
| 來源 | AI、台股、美股 RSS；保存原文與發布時間 |
| 圖像 | 程式產 1080 方形中文圖卡 |
| 觸發 | 每 30 分鐘掃描；沒有達標新聞就安靜 |
| 去重鍵 | 新聞來源 key／URL，發布前查 jsonl |
| 篩選 | 候選很多才批次評分；超過閾值才寫稿 |
| 節流 | 每次與每天按類別設上限，避免洗版 |
| 人工 gate | 預覽完整圖、文案、來源與敏感內容檢查 |

已驗證的教訓：

1. 本機圖片路徑不是平台可抓取的公開 URL。
2. Pillow 預設字型未必有中文；第一張要做真實視覺 smoke。
3. token 失效若沒有錯誤分類與告警，外觀只會是靜默停發。
4. 去重與節流要寫成 deterministic rule，不交給模型臨場自由發揮。
5. 固定排程不等於必須發；沒有合格素材時跳過是正確結果。

若使用者做商品、作品、課程或其他用途，只沿用決策卡、gates 與發布邊界；
來源 adapter、資料 schema、視覺系統與部署由執行 Agent 依 repo 補完。
