## 1. 成品會有什麼

完成後的小精靈可以：

- 透明顯示在 Windows 桌面最上層。
- 用滑鼠拖曳到任意位置。
- 頭部與眼神平滑追蹤滑鼠。
- 單擊、雙擊與右鍵觸發不同反應。
- 走路、跑步、跳高、睡覺、撒嬌。
- 讓球飛出去、落地彈跳、追球、撿回並放下。
- 在 50 秒到 5 分鐘之間隨機自主活動。
- 調整大小、暫停自主活動與設定開機啟動。

本教學採用 C#、WPF 與 PowerShell。原因是 Windows 10/11 通常已具備所需的 .NET Framework 元件，不必先建立龐大的遊戲引擎專案。

## 2. 準備工具與照片

### Windows 環境

建議準備：

- Windows 10 或 Windows 11。
- Windows PowerShell 5.1。
- 可執行程式與圖片處理工作的 AI Agent。
- Git，只有在需要版本控制或上傳 GitHub 時才必須。
- 能生圖的地方（建議 ChatGPT 網頁版）。不需要 API key，Agent 會把 prompt
  寫好給你貼過去，再把圖帶回來。

> **如果你是下載 ZIP 解壓縮取得這份專案，先做這一步，否則下面的指令會被擋。**
> 用檔案總管從網路下載的 ZIP 解壓出來的檔案帶有「來自網際網路」標記，
> `RemoteSigned` 執行原則不給跑這種未簽章的 `.ps1`。在專案資料夾跑一次：
>
> ```powershell
> Get-ChildItem -Recurse -File | Unblock-File
> ```
>
> 沒跑的話會看到 `... is not digitally signed`（中文版顯示「未經數位簽署」）
> 加上 `FullyQualifiedErrorId : UnauthorizedAccess`。這不是腳本有問題。
> 用 `git clone` 取得的檔案沒有這個標記，不必做這步。

執行環境檢查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File `
  ".\skill\windows-desktop-pet-builder\scripts\check-prerequisites.ps1" `
  -PhotoFolder "D:\你的寵物照片"
```

### 照片準備

建議提供 8～20 張清晰照片：

- 正面站立：2～4 張。
- 左右側面：各 2～3 張。
- 坐姿：1～2 張。
- 趴下或睡覺：1～2 張。
- 張嘴、伸舌、開心或撒嬌：2～4 張。
- 能看清眼睛、鼻子、耳朵、尾巴與腳掌的近照。

避免全部使用同一角度、強濾鏡、嚴重動態模糊或身體被裁掉的照片。

只使用自己拍攝或已獲授權的照片。不要把私人照片提交到公開 repository。

## 5. 建立角色視覺規格

不要一開始就生成所有動作。先讓 AI Agent：

1. 盤點照片角度與辨識特徵。
2. 列出不可改變的角色特徵。
3. 生成一張正面與側面身份確認圖。
4. 讓你確認臉型、眼睛、耳朵、身形、毛色與比例。
5. 確認後再生成動作素材。

建議規格：

- 半寫實 2.5D。
- 保留真實臉型、眼距、鼻型與身形。
- 同一光源、相機高度、毛髮細節與色溫。
- 純透明背景（**這是切圖後的最終規格**；向生圖工具下 prompt 時要的是
  「純白背景」，生圖工具做不出可靠的透明背景，之後再去背）。
- 不加入文字、邊框、陰影方塊或其他角色。

## 6. 製作透明動作素材

最低素材集合：

| 類型 | 建議張數 | 用途 |
|---|---:|---|
| 正面待機 | 1 | 基本顯示 |
| 分離頭部 | 1 | 頭部追蹤 |
| 分離身體 | 1 | 呼吸與身體動作 |
| 側面站立 | 1 | 起步與停止 |
| 走路 | 4+ | 自然步態 |
| 跑步 | 6+ | 追逐 |
| 坐下 | 1～2 | 點擊反應 |
| 跳躍 | 2～4 | 起跳、騰空、落地 |
| 睡覺 | 1～2 | 自主活動 |
| 撒嬌 | 2～3 | 點擊反應 |
| 低頭撿取 | 2～3 | 撿球 |

每張 PNG 都要：

- 透明背景。
- 固定畫布尺寸。
- 腳底或身體中心使用一致錨點。
- 相同方向命名；需要反向時由程式鏡像。
- 邊緣沒有白邊、黑底或殘留背景。

如果只有單張走路圖，程式再流暢也會像圖片滑行。真實追逐至少需要站立、跨步、騰空三個差異明顯的姿勢。

## 8. 做出自然的眼神與頭部追蹤

### 頭部

將頭部與身體分成兩個透明圖層。以頸部附近作為旋轉中心，根據滑鼠相對位置計算目標角度與平移，再用緩動逐步接近。

不要每一幀直接跳到目標值：

```text
current += (target - current) * smoothing
```

### 眼睛

讓瞳孔在小範圍內移動，並讓眼睛圖層與頭部共用旋轉和平移。

不要用純白橢圓蓋住原眼睛來模擬眨眼。頭部旋轉時，遮罩很容易留在舊位置形成白色殘影。較安全的方法是：

- 使用真正的閉眼素材。
- 或只短暫降低瞳孔與高光透明度。

## 9. 做出流暢且有物理感的動畫

### 不要使用每幀固定像素

錯誤方式：

```text
每一幀向右移動 9 像素
```

幀率變化時，角色速度也會改變。

正確方式：

```text
position += velocity * deltaTime
velocity = approach(velocity, desiredVelocity, acceleration * deltaTime)
```

建議：

- 更新頻率 8～16 毫秒。
- 使用高解析度計時器取得 `deltaTime`。
- 限制單幀最大時間，避免電腦卡頓後瞬間飛走。
- 起跑要有加速度。
- 接近目標要降低期望速度。
- 步態頻率要跟實際速度連動。

### 球的物理

球的飛行使用：

```text
x = startX + velocityX * time
y = startY + velocityY * time + 0.5 * gravity * time²
```

落地後加入：

- 逐次降低的反彈高度。
- 水平摩擦。
- 與移動距離一致的旋轉。

完整撿球狀態應拆成：

```text
蓄力 → 飛行 → 落地彈跳 → 追逐 → 低頭撿取 → 含球回程 → 放球
```

## 10. 加入互動與自主活動

建議互動：

- 拖曳：按住角色移動。
- 單擊：隨機坐下、撒嬌、跳躍或撿球。
- 雙擊：跳高。
- 右鍵：大小、自主活動、丟球、睡覺、離開。

自主活動：

- 一般模式在 50～300 秒間隨機觸發。
- 動作執行期間不要再次重入另一個長動作。
- 使用清楚的狀態機，避免球、角色與計時器互相衝突。

## 11. 測試、打包與安全

至少建立：

- `--self-test`：確認所有必要素材存在且尺寸有效。
- `--render-test`：輸出一張透明視窗渲染結果。
- `--fetch-test`：自動跑完整撿球流程，完成後回傳成功碼。

人工驗收：

- 拖曳後不會誤觸點擊動作。
- 眼睛左右極限沒有白色遮罩或殘影。
- 左右移動時鼻子朝向行進方向。
- 角色不會穿出螢幕。
- 改變更新頻率後，移動速度不會改變。
- 結束程式後，球視窗與系統匣圖示都會關閉。

### Windows 安全

未簽章 EXE 可能被 Smart App Control 阻擋。可選擇：

- 使用 PowerShell `Add-Type` 原始碼啟動器。
- 對正式發佈的 EXE 做程式碼簽章。

不要教使用者停用 Smart App Control、防毒軟體或其他系統保護。

## 12. 常見問題

### 眼睛移動後原位留下白塊

原因通常是眨眼遮罩沒有和頭部共用變形。移除純白遮罩，或改用真正的閉眼影格。

### 跑步像滑行

原因是只使用一張側身圖。補足多個腿部姿勢，並讓換幀速度跟移動速度連動。

### 角色倒著跑

先確認原始側身素材面向哪一邊，再決定鏡像符號。不要相信檔名，直接看圖片。

### 球看起來被直線拉出去

使用重力公式，不要只用線性插值。加入落地反彈、摩擦與撿取停頓。

### 改大後被裁切

限制安全縮放範圍，或讓透明視窗尺寸跟著角色縮放。

### 動畫速度忽快忽慢

所有速度、加速度與重力都必須乘上 `deltaTime`。
