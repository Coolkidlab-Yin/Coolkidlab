# Threads bot 陪跑流程

這是有終點的建置任務，不是持續循環課程。目標是從需求收斂走到可驗證的
dry-run；只有取得當次批准並完成真實 smoke 與回讀後，才進入全線完成。

## 每輪節奏

每輪只推進：

1. 1 個核心概念：只解釋這一步非懂不可的內容。
2. 1 個檢查：說清楚要看哪裡，以及什麼結果算通過。
3. 1 個動作：能安全完成就當場做完並驗證；有外部副作用就停在批准前。

新手先看 Agent 示範一個安全步驟，再共同完成下一步。登入、帳密、驗證碼與
機密輸入永遠由使用者處理。當使用者已理解同型操作，再提供可獨立重跑的命令
或檢查入口；不要求使用者猜技術步驟。

## 有限建置 Gate

- [ ] B0 目標：帳號、受眾、要省下的工作與第一版成功條件已收斂。
- [ ] B1 能力與憑證：repo、執行環境、瀏覽器路徑及 credential 名稱已確認；
      不收 credential 值。
- [ ] B2 設計：來源／輸入、觸發、狀態、去重鍵、人工 gate、紅線及資料保留已定義。
- [ ] B3 實作：最小元件、測試與 fake／mock adapter 已完成。
- [ ] B4 dry-run：以真實執行身分跑通，沒有呼叫平台，也沒有建立未批准的公開資源。
- [ ] B5 發布前檢查：確切帳號、完整內容／訊息、來源、成本、風險與批准範圍已顯示。
- [ ] B6 真實 smoke：只執行當次批准的一個最小真實動作。
      Threads：經批准後建立一次 container、publish 一篇，保存 container id／
      publish id 並回讀可見性。
- [ ] B7 回讀與交接：平台結果可回讀，id／狀態可追蹤，告警、停用與復原入口已驗證。

前一個 Gate 沒有證據，不進下一個。`--force` 或使用者催促都不能略過安全、
去重／冪等、配額、驗簽或批准。

## 進度檔

只有在 repo 實作會跨多輪，且使用者同意在專案內保存進度時，才建立
`threads-bot-progress.md`。教學規劃、單輪諮詢或沒有寫入授權時不建立。

~~~markdown
# Threads bot 建置進度
最後更新：[YYYY-MM-DD]
工作模式：[教學規劃 / repo 實作]
專案路徑：[路徑]
目標：[一句話]
目前 Gate：[B0-B7]
下一個可驗證動作：[只寫一個]
阻塞：[無 / 說明]

## Gate 證據
- [ ] B0：[證據或未完成原因]
- [ ] B1：[證據或未完成原因]
- [ ] B2：[證據或未完成原因]
- [ ] B3：[測試或實作證據]
- [ ] B4：[dry-run 命令、結果與時間]
- [ ] B5：[顯示內容與批准狀態]
- [ ] B6：[真實 smoke id；未批准填「未執行」]
- [ ] B7：[平台回讀、告警及復原證據]

## Credential readiness
- [credential 名稱]：[未準備 / 已安全保存 / 過期或需更新]
<!-- 只記名稱與狀態；不得記 token、secret、Authorization header 或驗證碼 -->

## 批准紀錄
- [時間]｜[動作]｜[帳號或目標]｜[批准範圍]｜[待批准 / 已批准 / 已拒絕]

## 已確認紅線
- [紅線]

## 下一次從這裡開始
[下一個畫面、命令或檢查；只寫一個]
~~~

更新進度檔前先讀取現有內容，保留先前證據與批准紀錄，不直接覆蓋成空白模板。

## 停點小結卡

每次暫停時只顯示：

~~~text
這次完成：[Gate + 實際證據]
目前停在：[Gate + 原因]
下一步：[一個可驗證動作]
需要你的批准：[沒有 / 明確動作與範圍]
目前完成度：[完成至規劃 / 完成至 dry-run / 全線完成]
~~~

不指派「功課」，不設冷卻日、Session 里程碑或無限維護循環。
